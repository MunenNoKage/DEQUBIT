## Name and source

**QEM-5Q** — synthetic quantum-error-mitigation dataset for 5-qubit circuits.
Generated locally by `generate_data.py` using Qiskit + Qiskit Aer.
No external data sources were used; everything is deterministic from fixed seeds.

## License and terms of use

Synthetic data produced by our own script. No third-party data is redistributed.

## Size and format

Four HDF5 files, ~4 files × (2000 or 200 circuits × 10 000 shots × 5 bits):

| File | Circuits | Shots each | Contents |
|---|---|---|---|
| `1_clean_train.h5` | 2000 | 10 000 | exact probs + clean shots |
| `2_clean_test.h5`  | 200  | 10 000 | exact probs + clean shots |
| `3_noisy_train.h5` | 2000 | 10 000 | noisy shots (same circuits as file 1) |
| `4_noisy_test.h5`  | 200  | 10 000 | noisy shots (same circuits as file 2) |

Bitstrings are packed with `np.packbits` (5 bits → 1 byte, shape `(shots, 1)`).

## Schema

Each file stores:

- **attrs**: `num_qubits=5`, `num_bricks=3`, `num_circuits`, `num_shots`,
  `split`, `seed_*`, `num_bitstrings=32`.
- **`all_bitstrings`** — `(32, 5) uint8`, the canonical ordering of all
  2⁵ basis states used by `probs`.
- **`probs/circuit_XXXX`** — `(32,) float32`, exact ideal probability
  distribution (statevector simulation, no measurements).
- **`qasm/circuit_XXXX`** — OpenQASM 2.0 source of the circuit.
- **`clean_bitstrings/circuit_XXXX`** or **`noisy_bitstrings/circuit_XXXX`** —
  `(10 000, 1) uint8`, packed raw shot outcomes.
- Noisy files additionally hold **`noise_model/`** group with the parameters
  used (`p1`, `p2`, `p_ro`, `T1`, `T2`, gate times, seed).

Unpack a shot: `np.unpackbits(row)[-5:]`.

## How to get it

Install these libraries:

```bash
pip install numpy h5py qiskit qiskit-aer
```

Run the generator from the repo root:

```bash
python generate_data.py
```

Outputs land in `data/`. Generation is fully deterministic — same seeds
produce byte-identical files.

## Splits

- **train**: 2000 circuits, seeds `42 + cid`.
- **test**: 200 circuits, seeds `9999 + cid` — disjoint from train.
- **Noisy pairs** reuse the *same* circuits as their clean counterparts, so
  clean ↔ noisy shot distributions can be matched per circuit.
- A single noise model (depolarizing + thermal relaxation + readout) is
  applied to both splits, so train/test share the same corruption process.

## Known limitations and biases

- **Fixed circuit family**: 3 "brick" layers of random single-qubit
  rotations (`rx/ry/rz`) plus random `CX` pairs. Not representative of
  structured algorithms (QAOA, VQE ansätze, etc.).
- **Single noise model**: one parameter set (p1=0.005, p2=0.02, p_ro=0.02,
  T1=80 µs, T2=60 µs). Real hardware drifts and is device-specific.
- **Ideal probs are exact statevector** — no shot noise on the target side;
  useful for supervised QEM but not a model of finite-sampling targets.
- **Small scale**: 5 qubits, 3 layers. Models trained here will not
  transfer to larger registers without retraining.
- **Readout + gate noise are combined**; separating them requires a
  calibration-style dataset not provided here.

## Version and checksum

- **v1.0** — generated by `generate_data.py` with the seeds documented above.
- Checksums: run `sha256sum data/*.h5` after generation and record here.

## If the data is too large or private for this pattern

- **Large but shareable**: the `data/` directory is small (< 200 MB) and can
  live in-repo. If it grows, use Git LFS or DVC.
- **Already hosted**: not applicable — regenerate from script.
- **DOI**: if a citable artifact is needed, upload the four `.h5` files to
  Zenodo with the generator script attached.
- **Private**: not applicable — no sensitive data.

> [!warning]
> Regenerating with different seeds produces a *different* dataset. Always
> record the seeds in the version line above so downstream results can be
> reproduced. Do not commit a modified `.h5` under the same filename.
